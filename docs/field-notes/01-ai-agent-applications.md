# 01 · AI agent 應用：從交辦到接手，而不是一個聊天視窗

對我們來說，AI agent 的價值不在於再做一個「可以問問題」的介面，而是把原本散落在瀏覽器、內部系統、文件與群組訊息裡的工作，變成可交辦、可回看、也可由真人接手的流程。

## 先把工作放到對的位置

短任務在 Lark 交辦：例如查一筆資料、整理一封來信、建立文件草稿、通知相關同事。群組是行動與溝通的地方，所有人看得到請求、進度與要確認的事項。

需要長時間查閱、比價、整理 PDF／圖片、保留來源與版本的事情，放到 cc web 的 project context。研究、開發與 IT 不是同一種上下文；把它們分開，才能避免 agent 把不相干的工具、記憶或資料帶到下一個任務。

真的要登入 ERP、信箱、文件服務或其他網站時，才由隔離的 Chrome 容器執行。AI 和真人看的是同一個 browser session：遇到首次登入、2FA、CAPTCHA、付款或不確定的外部送出，真人能接手完成，再把工作交回 agent。

```text
Lark 交辦／審核 ──→ cc web 研究與整理 ──→ 隔離瀏覽器執行
      ↑                                              │
      └────────── 需要決策、風險升高時由真人接手 ────┘
```

## agent 的工作不是取代責任

agent 可以先把重複、耗時且規則清楚的步驟做完：彙整資料、產出草稿、比對差異、更新文件、列出待確認項目。這讓人把時間放在價格、承諾、權限與例外判斷上，而不是反覆開分頁與複製貼上。

但它不應被設定成無限制的代辦人。對外寄送、付款、刪除資料、改變權限與第一次登入，預設都應保留人工確認或接手點。這不是犧牲自動化，而是讓自動化可以放心持續使用。

## 為什麼採用訂閱制 code agent

osslab-agent 不重造模型 runtime。Claude Code CLI、Codex CLI 等訂閱制 code agent 負責推理、工具調用與任務規劃；本架構處理的是 channel routing、session、project context、瀏覽器隔離與人機交接。

好處是推理層可以替換，工作流不必跟著某一家 API 綁死；日常任務也能在合適的訂閱方案下運作。敏感內容則保留未來接入本地模型或私有檢索的邊界，而非假設所有資料都適合送往同一個外部服務。
